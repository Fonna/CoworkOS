# 应用发版前本地验收手册

本手册细化第四环节的独立应用、TXT、CAD、Blender、PPTist 和 Computer Use。每次发版在本地使用候选 App 操作，按“准备什么 → 用户怎么操作 → 应看到什么 → 实际结果是什么”逐项检查。父 ID 对应 [五环节目录](testing-case-catalog.md)，如 TXT-01/create 是 TXT-01 的子项，不另建功能分类。已有自动测试与本手册的当前版本人工验收分别记录。

表内步骤是验收规格，固定素材及逐子项自动化尚需落地；已有 suite 可通过 [本地入口](testing-local-run.md) 复用并映射。当前功能和待实现的权限体验目标分开记录，不把未实现项记为成功，也不要求为了测试新增未公开的工具。

## 准备与共同体验标准

准备隔离用户目录、独立测试项目和真实最终 App，记录版本、源码状态、包 hash、macOS、引擎版本和模型连接。使用合成文件及测试窗口，正常桌面操作在真实 Mac 串行验收。Linux CLI 的领域入口复用适用的产物标准，不要求显示工作台。

C1 在两个引擎分别执行，仅对各引擎声明的导出格式验收。B1 的工程单位为 Blender 场景单位。T1 固定为 UTF-8、LF 换行、无 BOM、末尾一个换行。G1 基于现有 test/fixtures/computer-window.swift 扩展，姓名/备注/勾选项是待准备的素材规格；G2 先将 TextEdit 切为纯文本，再保存 .txt。素材可由固定脚本初始化；使用真实模型完成任务的变体必须从空文档/空场景开始。

每项同时记录功能和体验。体验的初始验收目标为：

- 点击后 1 秒内出现加载、保存或执行反馈；长计算可继续，但不能让用户猜是否收到操作。
- 普通编辑、保存和参数调整通过界面完成；不要求普通用户填写 revision、CAS、资源 ID 或写代码。直接编辑脚本的专属 case 除外。
- 错误提示包含可执行的下一步，保留用户内容；恢复能从界面进行，不要求删目录、重启电脑或手动修 JSON。
- 连续操作不抢焦点、不把用户读到的位置拉走；窄窗口下主要动作可达。控制名和成功状态用用户能理解的文字。
- 授权次数、额外确认次数、重复选择目标次数、模型向用户求助次数分别记录。超出范围的必要授权和同范围重复打断分开统计。

| PPTIST-07/artifact     | 导出 PPTX/JSON/PPTIST → 反复“在应用中打开” → 编辑保存重开；另导入外部 PPTX/坏文件 | 自己的导出物复用原资源/实例，仅一个 Tab 和加载项；原产物 hash 不变；外部文件独立导入；失败不创建空稿，CLI 不伪装转换成功 |
| PPTIST-08/print-backup | 使用打印/PDF → 核对系统保存文件 → 导出原生文稿 → 重新导入                         | PDF 真文件可打开且页数/文字/画面正确；原生备份包含媒体与源数据；打印事件不等同已保存 PDF                                 |
| PPTIST-08/limits       | 导入过大媒体、损坏富文本 → 保存；模拟不可信 iframe 消息                           | 数据拒绝有可操作提示、草稿仍在；不可信 origin/source/channel 不改文稿；合法富文本仍可编辑                                |

CASE-25 从空稿生成 P1，用户改主题和表格，Agent 局部修改，导出后回到原稿编辑并重启。结构检查与人工画面检查都要通过，不能把 layoutWarnings 为零当作字体和布局已验收。

## Computer Use 现行功能回归

现行代码为 Task+PID+windowId+bundleId 的单窗口授权、5 分钟有效期、30 秒单次观察凭据；暂停后重新开启，主页面刷新/关闭结束授权。这些是当前行为，不作为必须永远保持的体验设计。下表先确认已公开能力确实可用，下一节单列改进后的目标。

| 子项                  | 用户操作步骤                                                                 | 可见反馈与独立通过标准                                                                                          |
| --------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| GUI-01/onboarding     | 无系统权限首次打开“窗口访问” → 按引导开启权限 → 返回 CoworkOS → 刷新窗口列表 | 告诉用户缺哪项与下一步；已给权限不重复申请；回到原任务与原草稿，不要求重启电脑                                  |
| GUI-01/mode           | 对 G1 分别选择“观察”和“观察并操作” → 开启 → 查看当前授权条                   | 应用、窗口、模式、所属对话、时长可辨；观察可截图但不能输入；正常点击/输入在控制模式可连续执行                   |
| GUI-01/expiry         | 当前模式在到期前连续操作 → 临近到期查看 → 到期后再动作                       | 时长与实际策略一致；提示保留任务结果；到期停止未投递动作；如何继续明确；当前固定 5 分钟的打断记录为待改善体验   |
| GUI-02/observe        | 让 Agent 观察 G1 → 用户打开权限面板查看截图 → Agent 继续操作                 | PNG 和 AX 对应目标；查看预览不夺走 Agent 观察凭据；纯文本模型不能假装看图                                       |
| GUI-02/click          | Agent 观察后点击指定输入框/勾选项 → 再观察                                   | 实际焦点/勾选状态正确；有动作后反馈；“已发送”与“控件已改变”分开核对                                             |
| GUI-02/unicode        | 在姓名/备注输入中文、组合 Emoji、多行文本 → 保存 → 从文件读回                | 字节内容与 G1 精确匹配；长文本不截断；输入没有落到错误框或 CoworkOS 草稿                                        |
| GUI-02/shortcut       | 从观察取得当前焦点 → 全选替换 → Tab 切换 → Enter 保存                        | 操作发生于授权目标；最终字段与文件正确；快捷键执行完仍能继续对话                                                |
| GUI-02/effect-unknown | 动作已发送后抓屏失败 → 恢复观察 → 核对控件再继续                             | 不因为观察失败重复输入/点击；提示可恢复；已发生结果保留，最终保存内容没有重复                                   |
| GUI-03/move           | Agent 已观察后用户移动/缩放窗口 → 发旧动作 → 重新观察后重试                  | 旧坐标不误点击；错误可说明需重新观察；几何变化可自动重观察并继续，不因此重新请求同范围人工授权                  |
| GUI-03/another-window | 同应用开 A/B 两个窗口 → 只授权 A → 用户切到 B → 请求操作 A                   | 当前单窗口策略不会写 B；能恢复选择/激活正确 A；窗口名相同仍按身份区分                                           |
| GUI-03/save-dialog    | G2 未保存文档触发保存弹窗 → 观察弹窗能否在现有授权范围使用                   | 真实记录系统/应用弹窗的窗口身份；范围不足明确引导选择。重复授权次数用于评估下一节同应用模式，不能默认声称已支持 |
| GUI-04/takeover       | 连续动作中点击暂停或已注册的 Ctrl+Option+Esc → 用户手工改一段                | 待执行动作停止，已发送物理事件如实记录；状态变暂停，人工内容保留；继续入口易找到                                |
| GUI-04/pending-grant  | 开启授权回包慢 → 立刻暂停/结束 → 让旧回包到达                                | 不意外重新激活；状态与用户最后意图一致；输入留在原任务                                                          |
| GUI-04/task-end       | 运行中 Stop Task、切工作区、退出 App，分别测试                               | 操作按对应生命周期停止；授权状态可解释；重新启动不悄悄控制窗口                                                  |
| GUI-05/system-block   | 系统撤权/锁屏/安全输入启用 → 尝试观察/控制 → 用户恢复条件                    | 不乱输；说明真实系统原因；允许的观察仍可用；恢复后有明确继续路径，不丢任务和已保存结果                          |
| GUI-05/disconnect     | 工具请求中断连 → 服务恢复 → 核对授权/动作记录后继续                          | 已送出动作不重复，未送出的停止；当前授权是否结束准确显示；只让用户处理实际失效权限                              |
| GUI-06/real-app       | G2 TextEdit 新建合成文档 → 输入 G1 内容 → 保存到测试目录 → 重开              | 真实软件、保存弹窗和文件结果都正确；隔离窗口通过不能替代此项；只用当前公开动作，不假设有滚轮/拖拽工具           |

完整任务 CASE-12：用户提出“在这个文本窗口填写并保存” → 首次系统权限引导 → 一次明确授权 → Agent 连续观察/填写/核对/保存 → 用户中途接管改备注 → 明确继续 → 最终文件重读。授权与求助次数必须进入报告，不能只标工具成功。

## Computer Use 更少打断的权限目标

建议默认使用“本次任务允许操作”，用户开始时选择目标和范围，正常任务内连续动作不逐次确认。目标策略如下，均为待实现设计：

| 项目           | 目标行为                                                                                                      | 当前实现与验收状态                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 有效期         | 同 Task 授权最长 2 小时；15 分钟没有实际观察/操作自动暂停；界面提前提示并保留结果。普通状态轮询不续期         | 当前固定 5 分钟。修改策略后测边界；无需人工等待 2 小时，可用可控时钟测规则，真实长任务另验 |
| 连续操作       | 同范围的一组观察、激活、填写、快捷键和保存只需首次确认，后续没有授权弹窗                                      | 当前有效授权内已有连续操作能力；长任务与保存弹窗需补验                                     |
| 目标范围       | 默认所选窗口；用户可主动选择“此应用”，仅限选定应用的当前进程及其窗口，包括保存/打开弹窗；跨应用另由用户选择   | 当前只支持单窗口；同应用模式待实现，进程退出/PID 变化不继承旧权限                          |
| 暂停与继续     | 按暂停立即接管；“继续此任务”显示原目标，由用户一键确认，不重复走系统设置和目标选择。宿主复核目标，再重新观察  | 当前暂停后重新开启；一键继续待实现                                                         |
| 移动与短暂断连 | 同一身份窗口移动/缩放自动重新观察；连接恢复后核对尚有效的授权与已发送动作，不把连接错误当作每次都需要系统授权 | 窗口变化必须更新观察；当前断连有取消语义，恢复策略待实现；已结束授权不会自动复活           |
| 停止与可见性   | 授权条可见且能暂停/结束；Task 停止、应用退出或用户结束立即收尾；模型不能自行新增应用范围                      | 复用当前宿主与接管边界；范围与时间可以更宽，用户控制仍明确                                 |

宽松模式的具体子项：

| 子项                          | 用户操作步骤                                                                 | 通过标准                                                                                           |
| ----------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| GUI-01/continuous-friendly    | 一次授权后完成 20 次连续动作，并执行超过 5 分钟的正常任务                    | 首次目标确认 1 次，同范围运行中授权弹窗 0 次；无因旧 5 分钟时限突然失效；文件正确                  |
| GUI-01/task-duration-friendly | 在时限边界前操作；让无操作时间超过 15 分钟；Task 完成后再动作                | 活动期可用；无操作自动暂停且内容保留；Task 已结束后无动作；轮询不能保持控制权                      |
| GUI-03/app-dialog-friendly    | 用户选择“此应用” → 文档窗口触发保存/打开弹窗 → 返回文档 → 打开另一个应用窗口 | 所选进程的弹窗无需逐窗重选，保存完成；另一个应用不在范围内；同应用模式和单窗口模式各自遵守所选范围 |
| GUI-04/resume-friendly        | 用户暂停并手工修正 → 点击“继续此任务” → Agent 重新观察并只做剩余步骤         | 1 次继续确认、0 次重复系统权限请求、0 次重复目标选择；采用人工修改，无重复保存/输入                |
| GUI-05/reconnect-friendly     | 有效授权下短暂断连，目标身份不变 → 恢复 → 再模拟进程退出重启                 | 前者核对状态后可继续且不重复动作；后者原授权失效且明确选新目标，不把 PID 重用当原应用              |

只有改进模式准备公开提供时，这些目标才成为对应版本的必跑发布项。当前模式通过、体验目标未实现分别列出；不把安全拒绝用例通过误当作用户体验已经友好。

# M1 个人情境与已有安排：实现设计

对应[私人助理路线图](personal-assistant-roadmap.md)的 M1 情境基础。领域、存储、内部宿主服务和两条聊天路径已实现；HTTP 和设置管理在后续提交接入，不视为完整 M1 验收。专项正文暂为中文。

## 内部领域与持久化

[领域 schema](../src/domain/personal-context.ts)区分临时状态与已有安排。事实状态、业务状态与计算出的有效性分开；意向不等于确认，到期不推断康复或履约。临时状态必须有到期或复核依据，未知信息不能补造。

[快照存储](../src/runtime/personal-context-store.ts)位于用户数据根的 personal-context/context.json，与稳定记忆和 Task 分开。版本 1 保存 epoch/generation、快照版本、三个默认关闭的设置、记录、无正文事件、操作收据和消息身份屏障。通过短锁、私有临时文件、同步和原子替换提交；损坏或未知版本拒绝覆盖，达到容量上限保留既有事实。

有效写入只清理本模块精确命名的遗留普通临时文件，不清理其他目录或用户任务。删除清除情境正文和相关旧事件、抬升 generation，保留不含正文的身份屏障；原聊天、备份和已发送内容不在删除范围。

## 内部宿主服务

[PersonalContextService](../src/runtime/personal-context-service.ts)接收宿主提供的原始消息身份、原文、时间、用途、范围与权限，不接受模型自报授权。写入需独立语义判断；引用匹配只是附加条件。更新使用当前 ID/revision，消息及操作身份使重复提交幂等，设置变化或删除阻断旧提交。

读取检查 task/project/user 范围、用途、许可、敏感设置与当前有效性。执行许可必须有实时宿主授权，并在使用前校验版本；伪造、复制或跨请求/重启复用许可均拒绝。变化事件只带引用，尚无 Inbox 消费者，不创建目标或外部动作。

容量以领域 schema 为准：200 条记录、256 个事件、512 个收据、1024 个消息屏障、2 MiB 快照。没有自动迁移、清空屏障或恢复备份入口；人工恢复需停止宿主并更换 epoch 后验收。

## 验证

[边界回归](../test/personal-context.test.js)通过独立临时数据与进程验证持久化、范围、版本、删除屏障、并发与损坏保留。命令：node --test test/personal-context.test.js。测试中的语义回调不代表真实模型识别质量；聊天、管理界面和原生安装由后续提交单独验证。

## 跨对话聊天

[共享聊天适配](../src/runtime/personal-context-chat.ts)通过[薄工具](../.pi/runtime/tools/personal-context.ts)连接两条 Main/Pi 请求路径；宿主从原始用户消息取得身份、接收时间和引用。附件、内部续执行和压缩合成消息不能自发授予新保存权限。稳定记忆和目标交接保持独立。

manage_personal_context 支持 query/save/update/forget，保存独立检查归属、事实、范围、敏感性与保存意图，最多一次模型请求、不自动重试。仅兼容纯 JSON 或单个完整 JSON 代码块，仍使用严格 schema；引用只容忍空白展示差异并恢复可信原文。失败不会改写为记录已经撤销。

临时状态与计划事项使用不同合法状态及时间字段；同一消息只允许一次参数纠正，语义/来源拒绝或冲突后禁止换类型、标题或范围继续写入。模糊晚上不能新增猜测的钟点或失效时间；状态更新保留已有相同时间。返回 reminderScheduled=false，保存不会创建定时提醒或目标。

相关事项概览和具体规划共用准入，投影与查询最多 20 条、9000 字符；范围、敏感开关、代次和当前有效性仍需满足。旧查询按最新快照撤销，预算不足明确未完整检查。概览只读已登记情境，不代表外部日历或全部聊天历史检索。

回归：[聊天边界](../test/personal-context-chat.test.js)、[校验格式](../test/personal-context-assessment.test.js)、[真实 Pi 生命周期](../test/personal-context-pi.test.js)。最终聊天与格式 64 项、Pi 3 项通过；实模原文在隔离网页本次一次保存成功，曾发生的独立校验偶发失败不视为已全面解决。完整时间语义、恢复授权和完整 M1 待验收。

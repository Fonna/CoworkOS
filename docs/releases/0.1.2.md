# CoworkOS 0.1.2

This release fixes npm registry metadata handling in the Mac desktop installer and in-App updater. It also includes the npm desktop delivery and sidebar switch updates introduced for 0.1.1.

```sh
npx coworkos-app@0.1.2 desktop install
```

For the CLI only:

```sh
npm install -g coworkos-app@0.1.2
```

Both commands require Node.js 22.19.0 or newer and npm. The Mac App targets Apple Silicon on macOS 14 or newer, installs in `~/Applications/CoworkOS.app`, and includes its own runtime.

## Changes

- Compare the npm registry's `desktopRelease` metadata structurally, independent of JSON object key order. npm may reorder manifest fields in registry metadata; valid 0.1.1 desktop packages were rejected because their field order changed.
- Keep first-time desktop installation and in-App updates on the same `coworkos-desktop-darwin-arm64` platform package. Verify npm tarball SHA-512 integrity, the package file list and DMG SHA-256, then run the existing App identity, version, architecture and signature checks.
- Retain managed update staging, replacement after exit and rollback.
- Simplify the sidebar view switch: remove its separate border, background and inset shadow, and align its icon size and click area with the search and notification controls.

## Upgrade from an older App

An older App keeps the update URL embedded in its binary; publishing this npm release cannot change it. The installer protects existing Apps from replacement. To migrate once, quit CoworkOS, rename `~/Applications/CoworkOS.app` to `CoworkOS-legacy.app`, then run the desktop install command above. If the App is installed elsewhere, follow the same steps in that directory and pass `--directory /absolute/path` to the installer. After confirming the new App opens correctly, remove the old App in Finder.

Configuration, conversations and work remain in `~/.atria/` or the configured data location. Back up important data before upgrading. Updating or uninstalling the npm CLI does not remove the independent App or its data. Subsequent App updates use Settings; CLI updates use `npm install -g coworkos-app@latest`.

## Validation

The targeted desktop npm transport, installer/update controller, package builder, version metadata and CLI installer regression suites passed 45 tests. Formatting, documentation links and source hygiene checks also passed. The 0.1.2 light Mac DMG was built, image-verified and passed strict App signature checks.

The real 0.1.2 platform tarball passed the complete local installer in an isolated directory, including download, package integrity, manifest-order-independent validation, DMG checksum and strict App checks. Its Electron App launched with version 0.1.2, the sidebar control measured 32px without a border or shadow, and the App exited normally. This did not use npm's public transport or a separate clean Mac. The CLI candidate also passed 10 isolated local installation checks using an actual global npm installation.

Both `coworkos-desktop-darwin-arm64@0.1.2` and `coworkos-app@0.1.2` have been published to npm. Anonymous registry checks confirmed that both `latest` tags point to 0.1.2, both tarball URLs use the official npm registry, and both SHA-512 SRI values exactly match the locally accepted candidates. The additional anonymous npm download/install attempt was stopped during download and did not install an App. Complete public-network installation and the packaged in-App update check were not completed; the successful local installation above is separate evidence. The complete packaged desktop smoke was not rerun for 0.1.2, and native CAD/Blender components, clean-machine/Gatekeeper handling and real model providers remain unverified.

## Support and acceptance scope

The desktop App supports Apple Silicon on macOS 14 or newer. It uses ad-hoc signing and has no Developer ID signature or Apple notarization. If macOS blocks the first launch, use System Settings → Privacy & Security to allow it through the normal approval flow. Do not disable system protection.

Intel Mac, Windows and Linux desktop packages are not provided. CLI platform support and installation acceptance remain separate from desktop support. Third-party software retains its own licenses and corresponding source materials; see [third-party notices](../../THIRD_PARTY_NOTICES.md).

## 中文

本版修复 Mac 桌面安装器和应用内更新读取 npm registry 元数据的问题，并包含 0.1.1 的 npm 桌面分发和侧栏切换按钮改动。

```sh
npx coworkos-app@0.1.2 desktop install
```

仅安装 CLI：


## 改动

- 对 npm registry 中的 `desktopRelease` 清单做结构化比较，不受 JSON 对象键顺序影响。npm 会调整 registry 元数据字段顺序，导致 0.1.1 安装器错误拒绝本来有效的桌面包。
- 桌面首次安装和应用内更新共用 `coworkos-desktop-darwin-arm64` 平台包。先校验 npm tarball 的 SHA-512、包文件清单和 DMG SHA-256，再执行既有 App 身份、版本、架构及签名校验。
- 保留受管更新暂存、退出后替换和失败回滚流程。
- 简化侧栏视图切换按钮，去掉独立边框、底色和内阴影，并与搜索、通知控件统一图标尺寸和点击区域。

## 从旧版 App 迁移

旧 App 的更新地址保存在旧二进制中，发布 npm 新版本不会改写它；安装器也会保护已有 App，不会覆盖。首次迁移请退出 CoworkOS，将 `~/Applications/CoworkOS.app` 改名为 `CoworkOS-legacy.app`，再运行上面的安装命令。若 App 位于其他目录，按相同步骤处理并向安装器传入 `--directory /absolute/path`。确认新 App 可正常打开后，再从 Finder 删除旧 App。

配置、会话和工作仍保存在 `~/.atria/` 或原配置目录，升级前请备份重要数据。更新或卸载 npm CLI 不会移除独立 App 或用户数据；后续 App 在设置中更新，CLI 使用 `npm install -g coworkos-app@latest` 更新。

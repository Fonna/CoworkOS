# CoworkOS 0.1.1

## npm publication status

Only the `coworkos-desktop-darwin-arm64@0.1.1` platform package was published. The `coworkos-app@0.1.1` CLI package was not published, so the install commands below are unavailable. In addition, npm reorders the `desktopRelease` manifest fields in registry metadata; the 0.1.1 installer compares serialized field order and rejects that metadata. Do not use the 0.1.1 desktop package. Install `coworkos-app@0.1.2` after it is published.

Desktop installation and in-App updates now download from the official npm registry. This release also simplifies the sidebar view switch and aligns it with the search and notification controls.

```sh
npx coworkos-app@0.1.1 desktop install
```

For the CLI only:

```sh
npm install -g coworkos-app@0.1.1
```

Both commands require Node.js 22.19.0 or newer and npm. The Mac App installs in `~/Applications/CoworkOS.app` and includes its own runtime; Node.js is not needed to run it.

## Changes

- Use the same `coworkos-desktop-darwin-arm64` npm platform package for first-time desktop installation and in-App update downloads. CLI updates continue to use the `coworkos-app` npm package.
- Verify the npm tarball's SHA-512 integrity, its allowed file list and the DMG's SHA-256 before using the existing App identity, version, architecture and signature checks. App updates retain managed staging, replacement after exit and rollback.
- Stream desktop package hashing and DMG extraction instead of loading the full installer into memory.
- Remove the sidebar switch's separate border, background and inset shadow. Match the adjacent controls' icon size and click area while retaining hover and keyboard focus feedback.

## Upgrade from an older App

An older App keeps the update URL embedded in its binary; publishing this npm release cannot change it. The installer protects existing Apps from replacement. To migrate once, quit CoworkOS, rename `~/Applications/CoworkOS.app` to `CoworkOS-legacy.app`, then run the desktop install command above. If the App is installed elsewhere, follow the same steps in that directory and pass `--directory /absolute/path` to the installer. After confirming the new App opens correctly, remove the old App in Finder.

Configuration, conversations and work remain in `~/.atria/` or the configured data location. Back up important data before upgrading. Updating or uninstalling the npm CLI does not remove the independent App or its data. Subsequent App updates use Settings; CLI updates use `npm install -g coworkos-app@latest`.

## Validation

The full `npm run verify` run completed successfully, including build, lint, type checks, formatting, documentation links, source hygiene and release-runner checks. Its Node suite recorded 3,123 tests: 3,061 passed, 62 skipped and none failed. Targeted npm transport, installer/update controller and version metadata coverage passed all 44 tests; the sidebar browser suite passed all 4 selected cases.

The actual light Mac DMG was built and passed image verification and strict application signature checks. A focused check installed the real platform tarball through the complete installer, including download, DMG validation and strict App checks, then launched Electron, confirmed App version 0.1.1 and the sidebar button's 32px width without a border or shadow, and exited normally. This check used an isolated directory on the release Mac, not another clean machine.

The packaged desktop smoke passed TXT document/draft and attachment recovery across origins, human-reply recovery, a simulated upgrade, and quitting during an active task followed by task recovery. It also verified the bundled PPT editor, persisted edits and notes, and recovery after restarting a relocated App.

CAD checks passed basic-model editing by the user and a local Pi fixture, STL download validation, document/parameter recovery after exit, and source-model compilation with 14 objects. The complete generic desktop smoke remains unfinished: source CAD parameter editing, export and the final recovery checks still need acceptance after adapting the test to the current inspector UI. Native CadQuery and Blender checks were skipped because the light-package smoke disables those components in its disposable profile.

## Support and acceptance scope

The desktop App supports Apple Silicon on macOS 14 or newer. It uses ad-hoc signing and has no Developer ID signature or Apple notarization. If macOS blocks the first launch, use System Settings → Privacy & Security to allow it through the normal approval flow. Do not disable system protection.

Local validation does not establish acceptance on another clean machine, Gatekeeper handling of quarantined downloads, real model providers, microphone/accessibility permissions, or native CAD/Blender component delivery. These native and external checks require separate evidence. Intel Mac, Windows and Linux desktop packages are not provided. CLI platform support and installation acceptance remain separate from desktop support. Third-party software retains its own licenses and corresponding source materials; see [third-party notices](../../THIRD_PARTY_NOTICES.md).

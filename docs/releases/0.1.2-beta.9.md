# Atria 0.1.2-beta.9

本版改进命令取消、PPT 保存历史和 Watch 后台分析，并修复模型保存提示与请求重试记录。

## 下载与安装

- Mac：`Atria-0.1.2-beta.9-mac-arm64.dmg`，要求 macOS 14+、Apple Silicon，内置 Node 和 CadQuery/Python。
- CLI：`atria-cowork-cli-0.1.2-beta.9.tgz`，要求 Node >=22.19.0 和 npm；安装需要网络。
- 同时下载各自的 `.sha256`、发行清单及 Mac 签名记录。确切来源提交、tag、大小和校验值以本版发行清单为准。

{{MAC_SIGNING_NOTICE}}

校验 DMG 后拖入 Applications。当前 Mac 测试包首次打开按以下步骤操作：

1. 先尝试打开 Atria 一次。
2. 如果被拦截，进入 **系统设置 → 隐私与安全性 → 仍要打开**。
3. 再确认打开。

CLI 使用下载的 tgz 安装；尚未发布到 npm registry。完整步骤见 [安装指南](../getting-started.md)。仓库保持私有时，Release 仅对有仓库访问权限的用户开放。

## 本版内容

- 集成 main 上的 CLI Atria 产品身份、终端展示和本地反馈边界；交互 shell 使用 Atria 身份和输出文件名。
- 发布验收发现规则包含 ESM 和嵌套测试，保留真实执行统计及跳过项。
- 模型保存期间提示处理 macOS 钥匙串授权；拒绝授权时保留输入并提示重新打开应用后重试。原生自动回归使用独立测试钥匙串，真实系统授权单独验收。
- 请求重试遇到相同显示键时保留前一次请求记录，避免新旧请求在界面中相互覆盖。
- Unix 前台命令取消、超时及完成时回收普通后代进程，修复显式取消子 Agent 后命令仍继续执行的问题。Main 当前轮次中断仍允许已委派子 Agent 继续；持久命令使用 `start_job`。
- PPT 操作历史改为流式读取，大媒体使用内容寻址的外置历史共享，保留旧记录读取、幂等重试和撤销。
- Watch 分析使用独立 Run，不再覆盖 Main 的活动 Run、任务状态和完成标记；恢复队列保留该行为。
- 延续已有会话、项目与 TXT、CAD、Blender、PPT 工作台能力；具体行为以本版源码和验收记录为准。

## 验收与限制

构建、自动化、安装和真实模型分别记录证据。发布说明的验收补充记录给出本次实际结果；未执行、失败、跳过及其他版本的结果不得算成本版通过。

- 最终来源提交的自动化统计见 Release 验收补充记录；修复前基线的测试结果不能代替最终候选包验收。
- 先前候选已记录 Blender 界面一键安装、下载校验、刷新保持状态、几何生成、渲染和原生文件导出的真实操作证据；这些记录不代表本轮最终包已复验，本版实际覆盖以验收补充记录为准。
- 原生验收、CLI/DMG 打包和最终包核验的实际结果见本版 Release 验收补充记录。
- 真实模型、真实录音、最终包手动安装及升级：需要对本版候选包单独验收。
- 另一台无开发环境机器的安装未验证；Intel Mac、Windows、Linux 的本轮安装验收未完成。
- 前台命令后代回收本轮在 macOS 验证；Windows 仍仅管理直接命令进程，自行创建新会话或进程组的后代不在 Unix 组回收范围。
- PPT 新历史备份必须包含资源目录中的 `history-blobs/`；旧版本不能直接读取新外置历史，降级需恢复旧版备份。不同媒体和快照仍会增加磁盘占用。
- 默认 Mac beta 为 ad-hoc 签名、未公证，通过 DMG 手动替换安装，不提供 Developer ID 签名 ZIP 自动更新。
- Blender 需要另行安装。电脑操作需要系统权限与当前会话的人工窗口授权。
- CLI 安装仍会下载匹配平台的运行组件；不含桌面编辑器和 Swift helper。
- 私有 Release 的 App 更新认证接入尚未完成；可由获授权的用户下载后手动安装。

升级前退出任务并备份数据和外部项目文件，升级后核对历史、文档、草稿及模型连接。降级使用与旧版本对应的备份，不让旧 App 直接覆盖新版数据。

## English release summary

This release improves command cancellation, presentation history and Watch background analysis, and fixes model-saving guidance and request retry records. The Mac DMG targets macOS 14+ on Apple Silicon; the CLI requires Node >=22.19.0 and network access during installation.

The default Mac distribution is ad-hoc signed and not notarized. Install and upgrade manually using the verified DMG. For the current Mac test package, try opening Atria once. If macOS blocks it, go to **System Settings → Privacy & Security → Open Anyway**, then confirm opening. Blender is a separate dependency. Downloads from a private repository require repository access.

Build, automated checks, native checks, package inspection, installation/upgrade and real-model acceptance are separate evidence categories. This release's verification addendum records actual results; incomplete or skipped checks are not passes. A clean-machine installation on another Mac and other platform installations have not been verified in this release run. Preserve user data and project backups before upgrading.

Model saving now explains pending macOS Keychain authorization and how to retry after denial. Native automated fixtures use a separate test keychain; actual system authorization is verified separately. Automated counts for the final source revision belong in the Release addendum. Earlier candidate records cover real Blender one-click UI installation, download/integrity checks, reload continuity, geometry generation, rendering and native export. Those records do not certify this run's final package; current native acceptance and package results are recorded separately in the Release addendum.

This candidate also preserves previous request records when retry display keys collide, reclaims ordinary Unix foreground command descendants, and keeps Watch analysis Runs separate from Main's active Run and Task state. Interrupting Main's current turn still leaves delegated subagents running; persistent commands use `start_job`. Windows still manages only the direct command process, and descendants that create their own sessions or groups are outside Unix group cleanup.

Presentation operation history now streams legacy records and shares large media through content-addressed external payloads while retaining idempotent retries and undo. Backups must include each resource's `history-blobs/` directory. Older versions cannot read the new external history; downgrade by restoring an older-version backup. Distinct media and snapshots still consume disk space.

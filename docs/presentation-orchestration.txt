PPT 制作编排

现行流程见 docs/presentation-workflow.md；组件字段和逐页设计见
.pi/skills/presentations/references/。本文件只列编排约定。

绑定 PPTist 文稿继续使用应用工具读取、原子修改和导出，保留原生源文件。
独立 PPTX 使用 presentations 技能；加载后使用返回的实际脚本路径。
先规划受众、逐页结论、来源和视觉，再制作可编辑对象。素材清单不是看图证据。
一位 async 协作者可以核对独立资料，Main 同时制作；保持一位文稿作者。

通过已有模型连接角色选择图像分析连接；不新增独立的视觉设置配置协议。
启用视觉能力且存在该连接时可用 review_slides；主模型原生读图仍使用 read_image。
将全部最终页与 contact-sheet overview 放在一次批量调用中，默认 concurrency=2，
提供方容量已知时最多 4。slides、overview 遵守选定的图片根与 scope：
Main 默认 scope=project，子智能体默认 scope=work，共享 Task 图片使用 scope=task。
reportPath 独立使用 Agent 自己的报告目录，Main 为 Task 的 agents/main/work/，
子智能体为自己的工作目录；返回 reportScope=work。Task 只读图片范围不授予共享写入。
报告路径可相对该目录或为其内部绝对路径，JSON 报告不得覆盖框架状态。

批量队列在任意 worker 完成后取下一页，增量保存真实结果和尝试历史。
修订后沿用 reportPath 和逐页 goal，再提交全部最终页，以复用未变化的证据。
everySubmittedPagePassed 仅覆盖提交页，不能证明整份 PPT 已全部覆盖。
无批量工具时用 read_image 按 scope 逐页检查，相对路径或选定根内绝对路径均可；
联系表不能替代单页。
失败、取消和未检查不能作为通过，不得手写通过记录或改变目标绕过重试上限。

结构验证、真实渲染、视觉检查及事实核对分别提供证据。
默认集中修一轮，再统一重建/渲染和复查；第二轮仅针对剩余重大缺陷。
最多重试一次失败检查，最终明确报告未检查页与未解决问题。
Main 使用 publish_artifact 发布已验收文件；Subagent 候选留在自己的 deliverables/。

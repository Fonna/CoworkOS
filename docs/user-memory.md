# 跨任务用户记忆

用户记忆保存稳定的偏好、背景和项目约定，供新 Task 使用。它不同于每个 Task 的 `agents/main/context/memory.md`。可以明确要求保存，也可以开启后台自动学习；不需要反复说“请记住”。

个人记忆模块不生成或修改 `SKILL.md`。独立的[项目经验与技能](project-experience.md)提供按项目授权的后台经验候选、证据复核、技能版本与回滚；其默认开关、数据范围、容量和模型额度与个人记忆分开。Task 内原有的 `memory.md` 和实验台账仍用于当前任务的恢复与迭代。项目技能演进不训练模型，也不等于自动重放技能或经过真实模型 A/B 证明有效。

## 现有设置中的开关

在原有设置页面分别控制记忆使用与自动学习，新用户两者默认关闭：

- “个人记忆”：控制是否向模型提供已有记忆。单独开启不会开启自动学习；可只使用手动填写或明确保存的偏好。
- “自动学习”：默认关闭，独立选择是否从用户表达中后台整理偏好，可能产生额外模型请求。开启后静默筛选，不主动询问是否保存、不要求确认候选、不在聊天中播报整理结果。关闭它不影响使用已有记忆。关闭“个人记忆”时学习暂停，保留学习选项、已有记忆及待处理输入，重新开启后按原选项继续。
- “查看记忆”：直接编辑一份完整正文，总长最多 2000 个字符（JavaScript 字符串长度，部分 emoji 占两个单位）。打开时读取已有正文，保存时替换整份内容；清空后保存即可删除正文。关闭开关后仍可编辑，不会因此开启使用或整理。草稿在关闭详情后保留，整页刷新不保留。冲突不覆盖输入，可复制草稿，再取消修改以读取最新记忆。

旧版多条用户记忆按原顺序合并显示，不自动截断或删除；超过 2000 字符时提示用户精简，保存前保留原文件。旧项目范围记忆继续按原项目隔离，不混入跨项目正文。

旧文件中 enabled/learningEnabled 的值分别保留，缺少学习字段时按关闭读取，不自动扩大数据处理范围。`set_enabled` / `enable` / `disable` 只控制使用；`set_learning` / `enable_learning` / `disable_learning` 独立控制自动学习。开启个人记忆后，可在对话中明确保存、查看、纠正或删除。关闭时，模型侧管理工具只返回开关状态和空条目，不提供记忆正文；若已知条目 ID 和版本，仍可明确删除。设置页可以继续查看与编辑，不会因此把内容提供给模型。

升级时退出共用用户目录的旧宿主。新版本读取缺失的配置、用量和候选字段时使用缺省值，候选集合默认为空，第一次写入时补齐；已保存的记忆保持原样。旧版本的严格文件校验不支持这些新增字段。需要回退时先备份记忆文件，再恢复升级前备份，避免新旧宿主交替写入。

“自动学习设置”可指定当前连接支持的后台模型（留空使用当前连接模型），单次输出上限为 256–4096 tokens，默认 2048；后台关闭推理，不继承前台的大输出预算或推理档位。每小时请求上限为 2–24 次，默认 6 次，按最近一小时的持久记录计算，多宿主和重启共用。提取与压缩各计一次，已预约但随后取消的请求也计入；最小值为 2，以便一次提取后还能压缩。达到上限时保留输入，不消耗失败重试次数，额度释放后继续。调整模型、开关或上限不清除已用额度。此限制控制请求次数与单次输出，不能换算为固定费用。

删除或关闭不会撤回已经发送的请求，也不会抹除旧会话、工具结果、请求记录和导出。失败请求重试时会刷新宿主管理的个人记忆段；其他历史保持原样。用新 Task 验证遗忘效果。

## 后台提取与整理

用户消息被接收后尝试将用户原文持久化到轻量接收队列，不依赖任务成功。Dashboard 在保存已接收消息后入队；Pi 宿主在开始执行前入队；程序化 Main 对非恢复输入在执行前入队。前台不合并、解析或改写整个学习队列；接收队列锁短时繁忙或写入失败时跳过本次学习，不让普通任务失败。不提交助手输出、工具结果或完整执行轨迹。输入做长度限制，并过滤附件上下文块、代码块、引用行和部分常见密钥形式；“不要记”“忘记”等遗忘请求不进入自动学习。过滤是有限规则，不是对所有敏感内容的识别保证。

输入至少闲置 60 秒才有资格处理。轻量接收队列最多保留 30 个 Task，每个 Task 最多八份原文、每份最多 6000 字符；闲置后由后台合并到原有待处理队列，后者最多 30 个 Task，每项合并正文最多 6000 字符。同一 Task 后续输入合并并重新计时。活动标记独立于学习输入，即使用户只发短消息、过滤后没有可学习内容或内部继续运行，也会阻止其他宿主整理；标记按宿主进程和运行身份分别释放，旧 Run 结束不会释放新 Run。成功、失败、取消和等待均可释放活动标记，不要求 Task 完成。正常关闭保留输入；重启后清理已死亡本机宿主的标记，仍存活的宿主不会被抢占。单纯暂停或调整学习配置保留接收队列，手动修改记忆则使旧证据失效。

Dashboard 启动时检查一次，此后每 15 秒检查一次，每次最多处理一个合格项。15 秒是检查周期，没有合格输入时不会请求模型。任一前台运行结束后，后台还需等待共享的 60 秒安静窗；短消息或被过滤的输入也会重新计时，避免刚结束续跑就整理旧输入。后台沿用当前连接的地址、凭证、协议及上下文窗口，并使用独立的模型选项、输出上限和请求额度；凭证不写入队列。切换连接会使旧轮次失效；提取后再次检查连接，不继续向旧连接请求压缩，也不提交旧结果。切换与前台抢占不计为提取失败，输入留待下一轮。

前台任务优先：Dashboard 有任何任务正在启动或运行时不启动整理，前台启动会取消本宿主在途整理；独立 CLI 在当前交互执行时暂停，程序化 Main 执行期间也不整理旧输入。取消保留输入，不计为一次提取失败；已经发出的请求仍可能产生用量。共享数据目录的其他本机宿主通过独立活动标记参与抢占；后台在途每 100 毫秒检查轻量标记与配置投影，发送请求和提交结果前再次检查，不反复解析整个学习队列。这不是操作系统或远端 API 的优先级保证。退出时停止定时器、取消请求并释放本运行的标记；队列跨重启保留。一次性 CLI/程序化调用退出后，未处理输入由后续常驻宿主或闲置会话继续处理，不单独延长进程生命周期。普通任务仍有本地读写和锁操作，但不等待后台模型提取结果。

学习模型不提供工具，只返回最多五个结构化候选，每条最多 500 字符。每个候选必须包含用户原文引用、范围、长期有效性判断及证据类型 `direct` / `observed`；临时或不确定候选不写入。只识别稳定偏好、自述背景和清楚的纠正，不推测敏感个人特征、不从单次任务成功推断偏好。项目约定保留 project 范围。

正式记忆有两条准入路径。明确、稳定的第一人称自述或明确的长期项目约定可以直接纳入；模型标注 `direct` 后，宿主仍以保守的语言规则复核原文，第三方、代写/角色扮演、假设和单次要求不能据此直接保存。其他偏好先成为内部候选，至少得到三个不同 Task 的独立支持才纳入；同一 Task 的不同 Run、重试和重复接收都只计一次。缺少证据类型时按较弱候选处理。含糊的身份背景或约束不走重复观察晋升路径。证据强度和独立支持次数由宿主判断，不接受模型提供的计数。

候选最多 20 条，每条正文最多 500 字符、最多保留三个 Task 的哈希标识，首次观察后 30 天过期；不复制来源全文。候选与正式正文分开，不注入前台上下文，也不出现在管理工具或设置 HTTP 响应中。后台下一次提取可以看到同范围候选的正文以合并表达，但候选本身不构成新证据。手动保存、纠正、删除会保守清理同范围的旧候选；用户正文替换会清理用户级候选。超过限额和过期清理均在后台结算时处理，不打断任务。不同项目、用户级与项目级支持分别累计。

模型可以跳过已有的相同语义，或引用已有自动记忆的 id/revision 更新它。程序验证引用存在、版本及范围一致，做精确重复检查；不会允许后台静默覆盖手动保存/纠正的条目。语义合并和“是否长期有效”仍依赖模型判断，未证明完全准确。

保存前在锁内再次检查开关、队列和 generation。切换开关、学习配置或手动保存/纠正/删除会更新执行代次但保留队列，防止旧响应直接落盘；再次确认已有的同内容条目也会使旧响应失效。删除或手动纠正只保护当时待处理的旧来源：按记忆 ID、原文引用包含关系及正文相等识别相关候选，其他候选可在新代次重新处理。明确保存命中已有自动条目时会保留 ID 并升级手动来源及版本，使后台更新和压缩不能改写。后续新 Run 的表达仍可学习；这不是永久屏蔽。引用无关、语义改写的冲突仍依赖模型识别，规则不能保证识别所有语义等价。同一输入有确定性标识，最多保留 200 个已处理标识；重复接收同一输入不会覆盖此前合并的原文。学习锁防止多宿主重复推理，并恢复已死亡宿主的锁。提取与可选压缩合计最多 60 秒，不在 SDK 内自动网络重试。异常、不合法或未完成响应保留输入，记录不含原始错误/密钥的失败标识；第一次失败后等待 1 分钟，第二次后等待 5 分钟，同一份输入最多尝试 3 次，耗尽后保留输入但不继续自动请求。新增用户输入会建立新的重试批次。有效的空候选正常结算。前台抢占和正常退出取消不增加失败次数，队列跨重启继续处理。

## 范围与保存

默认存储在 CoworkOS 用户数据目录的 `memory/user-memory.json`，即 `ATRIA_HOME` 下；没有设置时使用默认用户目录。当前按本地数据目录区分用户，不是多账号系统。Task 工作区位置变化不搬迁用户记忆。

同目录的 `.profile.json` 投影只含正式条目、开关和调度摘要，不含候选和原文队列；前台通过文件指纹和进程内缓存读取它。原文件变化、投影缺失或损坏时从原文件重建，旧文件首次迁移仍需完整读取。`.inbox` 与小索引保存待后台合并的原文，`.activity` 保存不含用户正文的运行标记，`.quiet.json` 保存安静窗截止时间；这些文件使用私有权限和原子替换。原文件和接收队列都可能包含本地明文用户表达，不是密钥库。

- `user`：跨项目提供，仅在与当前任务相关时使用。
- `project`：宿主提供的项目绝对路径必须相同。移动目录或符号链接别名可能需要重新整理记忆。
- Subagent 不自动获得记忆库和管理工具，Main 仅按需要传递相关背景。

每条记忆保留内容、分类、范围、版本和来源。自动条目标记 `origin=automatic`，手动工具标记 explicit，设置 API 编辑标记 settings。队列只在自动学习开启时收集新输入，暂停期间保留已有输入但不收集新输入；旧版文件缺少相关字段时默认不启用学习，按兼容缺省值读取。

记忆正文总预算为 2000 字符（含分隔换行），不是每条 2000 字符，不再设置 200 条的产品容量。内部保留来源片段与版本，供自动合并、原文校验和旧项目范围兼容；界面不再展示条目卡片。手动/工具保存超过总预算则拒绝。只有已经通过准入、确实将超过正文预算的新记忆，才额外调用后台模型整体精简当前范围内的自动记忆，再与新记忆原子保存；仅暂存的弱候选不触发压缩。每条自动记忆保留原 ID、人物归属、范围和来源，不删除条目；手动/明确保存内容及其他项目内容不参与改写。压缩前后校验完整快照，编辑、关闭或删除使旧结果失效。提交压缩结果时，在同一事务内重新预检准入与容量；若支持已过期或变化，当前可准入内容无需压缩即可容纳，就忽略压缩结果，只提交当前通过准入的变更。压缩不合法、空间仍不足或调用失败时，原记忆与输入保留，沿用有上限的重试；不截断正文。语言规则不是完整的语义证明，候选合并、冲突识别和压缩准确性仍需真实模型评估。

每次请求按项目过滤后以更新时间排序，正文预算为 2000 字符，整段 `<user_memory>`（含 JSON 元数据、转义和说明）另有 6000 字符硬上限。只选入完整条目，装不下时保留原文件并提示用管理工具查看；该上限不包括工具定义及其他系统提示。不是向量检索，也没有根据当前问题做语义相关性检索。存储采用文件锁、校验、私有权限和原子替换，损坏文件不会被静默覆盖；数据锁使用短超时及死宿主恢复，避免长时间阻塞普通任务。文件包含本地明文记忆、来源与待处理的用户输入，不是密钥库。

最后发送前，程序化 Main 与 Pi 宿主还会把记忆纳入完整系统提示、工具定义和消息的上下文估算，并预留输出预算与当前模型的压缩保留额度。完整记忆段装不下时本次静默省略，不为记忆压缩或裁剪用户当前输入。重试原请求也对归档上下文重新检查这一预算。估算采用现有 SDK 算法及已有模型用量的保守值，不等于所有提供商真实 tokenizer 的精确计数。

常规前台读取和在途检查的工作量不随内部学习队列增长；后台合并、预约用量和提交仍需读写完整原文件，JSON 处理与 Dashboard 共用 Node 事件循环。大文件可能造成短时延迟，不能据此保证后台整理对响应时间完全没有影响。

## 执行与管理

[存储](../src/runtime/user-memory-store.ts)、[后台学习](../src/runtime/user-memory-learning.ts) 和 [工具](../src/runtime/user-memory-tools.ts) 被两条 Main 路径复用。PiSession 每次请求刷新记忆投影；Pi 宿主在 `context_with_system` 刷新。当前用户要求优先，记忆不授予权限。读取失败不阻塞普通聊天，管理工具会报告问题。

失败 Main 的“重试原请求”保留原模型、发送地址、参数、执行归属、用户输入和工具历史，只刷新宿主管理的个人记忆段；关闭、删除和编辑立即影响这次重试的记忆投影。记忆未变化时保留原序列化正文。若旧载荷无法安全对应到归档系统正文，则发送前拒绝重试并保留原请求与历史，避免重发已撤销的记忆。已存在于用户正文或工具历史中的相同文字不按字符串匹配删除。

`GET /api/user-memory` 返回设置、`learningOptions`、合并的 `content`、整份快照 `revision` 和兼容来源条目，不暴露内部队列、未确认候选、已处理标识或请求用量时间戳。`POST` 支持 `save_text`（`content` 可为空，最多 2000 字符，必须携带 GET 返回的整份快照 `revision`），原子替换用户正文；后台旧响应不能覆盖编辑。`set_learning_options` 接收完整 `options`：可选 `model`、`maxTokens`、`maxRequestsPerHour`，省略字段使用缺省值。保留 `remember`、`set_enabled`、`set_learning`、`update`、`forget`。使用 Dashboard 原有本机地址、Origin、会话认证和禁止缓存机制。旧条目修改/删除必须带当前条目 revision。

明确保存的工具只用宿主保存的用户正文校验原文，排除文本附件；Pi 宿主也接受当前 Task/Run 中已经回答的持久提问原文（不包含未回答问题、超时推荐项或其他工具输出），来源身份由宿主写入。缺少可信正文且有附件时不接受附件作为授权；普通 CLI 文本仍可直接引用。引用匹配不是对自然语言授权的完整语义证明。程序化恢复没有新输入时不允许借旧 prompt 做手动记忆修改；初始化失败也会释放待整理输入的活跃状态。

## 验证与边界

CLI 构建后运行 `node --test test/user-memory*.test.js`。测试使用临时用户目录、本机假模型和真实 Pi 调用；浏览器测试为 `e2e/user-memory.spec.js`，检查现有设置中的开关及重启保存。自动生成内容的真实模型质量、多用户权限和模型用量统计仍需专项验收；不声称等同 Codex 内部实现。

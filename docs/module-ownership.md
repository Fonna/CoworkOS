# 模块所有权与协同

功能入口、消费者和测试见 [代码地图](code-map.md)，依赖规则见 [架构](architecture.md)，提交规则见 [CONTRIBUTING](../CONTRIBUTING.md)。

下表定义职责角色，尚未填写真实人员/GitHub ID；配置 CODEOWNERS 和分支保护前，由维护者承担审核。同一人可负责多层，跨接口仍应由另一位开发者复核。

| 模块                                            | 主责角色                     | 变更需要协同     | 最低验证范围                                               |
| ----------------------------------------------- | ---------------------------- | ---------------- | ---------------------------------------------------------- |
| `scripts/atria.mjs`、`src/cli/`                 | CLI 负责人                   | 运行时/发布      | init/doctor、参数、无仓库 tgz 安装、配置兼容               |
| `web/` 控制器、工作台、领域 UI                  | 前端负责人                   | 应用/服务接口    | 草稿归属、保存/冲突、Tab、SSE、键盘与窄窗口                |
| `src/dashboard/` HTTP/SSE                       | 服务接口负责人               | 前端/运行时/应用 | DTO、状态码、认证、请求限制、异步消费者                    |
| Dashboard Run、Runtime、ProcessHost             | 运行时负责人                 | 桌面/Pi          | 状态裁决、Inbox、委派、取消、退出、恢复与真实进程          |
| `src/applications/`、`src/software/`            | 应用协议负责人               | 前端/Pi/运行时   | revision、共享资源/外部写入、迁移、真实几何/原生文件与导出 |
| `src/gui/`、`src/security/`                     | GUI 与执行安全负责人         | 桌面/应用        | 窗口目标授权、串行、过期/取消、真实原生状态和审计          |
| `.pi/runtime/`、`.pi/skills/`                   | Pi 接入负责人                | 运行时/应用      | 首轮 hook 顺序、工具发现、视觉/文本结果、实际 Pi 生命周期  |
| `src/workspace/`、`src/storage/`、`src/domain/` | 数据与运行时负责人           | 所有消费者       | 格式、路径归属、备份/迁移、恢复与共享写入                  |
| `desktop/`、构建/打包/CI                        | 发布负责人                   | 运行时/GUI/安全  | 首次配置、可信 IPC、退出/重启/升级、包搬移、签名/许可      |
| `test/`、`e2e/`、验证脚本                       | 验证维护者；能力主责维护断言 | 对应能力主责     | 用例发现、非零失败、临时目录、明确跳过、证据范围           |
| 现行文档与双语入口                              | 对应能力主责；文档维护者导航 | 命令/接口消费者  | 路径/锚点、语言对、功能与接口准确性                        |

## 接口两端审阅

- HTTP/SSE：服务接口负责人 + 消费 UI/CLI。
- Adapter/软件驱动：应用协议负责人 + Pi/前端消费者。
- Task/Run/事件/checkpoint：运行时/数据负责人 + 对话投影/Pi/桌面恢复消费者。
- 可信 IPC/执行权限：发布/GUI 负责人 + 运行时消费者。
- 第三方升级或许可/发布内容：引入模块负责人 + 发布负责人。

新增模块必须说明状态所有者和上/下游接口，登记到代码地图；测试和文档由功能主责一起维护，不交给独立目录自行变旧。实际人员分配与强制审核配置仍由维护者确认。

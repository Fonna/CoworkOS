# PPTist collaboration

For narrative planning and final visual QA, load `presentations` as well. Plan each page's audience, takeaway, evidence and primary visual before drawing; keep typography and margins consistent and split dense content instead of shrinking fonts. This skill's application tools remain the authority for editing the bound document.

For a new presentation, enable the applications tool group, then create_resource with kind `presentation/pptist+json`. The editor is the actual PPTist application. Its saved document is authoritative. Begin each request with `pptist_read_presentation({})`, omitting slideId to obtain the current outline. Each outline entry has a page number and a real id; copy its id into slideId to read the slide you will edit. Never guess IDs from page numbers or names such as `1`, `intro` or `slide-1`. Read `pptist_get_schema` for element examples; its IDs only illustrate new slides/elements and do not identify existing slides. If a slide is missing, use the error's nextAction to reread the outline and choose an actual id instead of trying more guesses. Do not edit the backing file directly.

Use `pptist_edit_presentation` for atomic changes. Update an existing element by id, supplying only the changed fields. Omitted properties, especially embedded image/audio/video data, are preserved. Read results replace base64 with explanatory placeholders: never write these placeholders back. Preserve user text, notes, theme, unrelated elements and slide order unless asked to change them. A revision conflict requires reading again and adapting the changes, not blindly repeating an overwrite.

Coordinates default to a 1000 × 562.5 page. New text added with `pptist_edit_presentation` has zero inset by default. Existing/imported text without an explicit inset has 10 px on each side: subtract padding when sizing text. For page numbers use the schema's `pageNumber` example (100 × 32, 18 px, inset [0,0,0,0]); fixedHeight does not prevent wrapping or shrink fonts. Use margins of 50–80, title text 36–52 px and body text 22–30 px. Check each element's bounds and overlaps. Text is HTML using p/span/strong, with explicit CSS pixel font sizes. Use fixedHeight=true when a text box should keep its assigned height; otherwise the editor adapts it during manual editing. Speaker notes are slide.remark. Use simple layouts and a consistent theme. Ask only for information that materially affects the deck; do not invent data or attribution.

The read tool provides the outline and element data, not a rendered visual preview. Read changed slides again to check structure and content, and resolve all returned `layoutWarnings` before export. Then use the `presentations` helpers to validate and render the exported PPTX, inspect every final page with `read_image({review:true})`, and save review status/issues against the final image hashes. A contact sheet only checks consistency. Fix issues through `pptist_edit_presentation`, export again, and re-review changed pages; preserve the native document. Allow one retry per failed review and two repair rounds. Missing renderers or failed checks are unreviewed and must be reported explicitly.

`export_resource` supports json, pptist and pptx. JSON and PPTIST retain the full native document, including animation settings. The headless PPTX exporter handles basic text, shapes, embedded media, charts and tables; use the editor's full PPTX exporter for detailed visual styling, or image export for visual fidelity. PowerPoint round trips are compatibility conversions, not lossless source backups. Save the native source alongside a PPTX deliverable. The editor also supports images and the system PDF print dialog.

Media must be embedded base64 data or HTTP(S) URLs; local file paths and temporary blob URLs are not portable. Headless export does not fetch remote media. The document limit is 32 MiB, 200 slides and 500 elements per slide. Use compressed images and modest media sizes. AI requests run through CoworkOS; do not call PPTist's hosted AI services.

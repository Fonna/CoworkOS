# 设计与验收

## 内容决定视觉

用用户的品牌、主题、材料和真实内容确定页面性格。先写出受众、主要任务、视觉锚点，以及字体、色板和布局选择的理由。已有设计系统优先；新设计将表达重点集中在一个清楚的区域，其余元素服务阅读和操作。

## 排版与空间

统一字号、字重、行高、内容宽度和间距刻度。字体必须在交付环境可用，并提供中英文 fallback。留白用于分组和主次；组件边界由内容撑开，避免用固定高度制造空洞。

使用真实长标题、多行中文和边界数据检查布局。断点来自内容是否仍可读，而非仅来自设备名称。视觉差异应编码实际分类、状态或权重，编号只用于真实顺序。

## 文案与状态

以用户认识的对象和动作命名控件。按钮写出实际结果，同一动作在按钮、提示和历史中保持同名。错误解释原因和恢复动作，空态提供下一步。标签、说明和示例各有明确作用。

图表使用一致分类、单位和色板，数字对齐且格式统一。图片保持比例，截图优先完整展示重点区域。不要把装饰或示例图片当作事实证据。

## 交互与可访问性

语义标签、键盘导航和焦点可见。检查文字对比度、触控目标、加载、失败和重复操作；弹窗关闭后恢复焦点。动效帮助解释状态变化，尊重 reduced-motion。

## 实际验证

使用项目构建及检查流程。通过本地 HTTP 检查桌面、窄屏、资源、控制台和主要交互，截图以当前渲染为准。`read_image` 可以检查引用图片或截图，`paths` 比较最多四张图片；对最终每页或长页每段的审阅分别执行。

截图能证明可见布局，不能证明点击、持久化或下载成功。交付入口、相对资源和必要数据，说明实际执行的检查和未验证部分。
